## Текущий контракт: очередь допуска

Владелец подтвердил реализацию очереди и публикацию исправления в `main`, затем
явно согласовал числа: 4 ожидающих с IP, 64 на экземпляр, максимум 5 секунд,
затем 429. Общий интервал допуска PostgreSQL не меньше 1000 мс/IP сохранён.
Очередь охватывает прежние ограничиваемые маршруты; исключения не расширены.

Исходный дефект: SDK 1.30.0 не мог завершить обычный handshake из-за немедленного
429 на initialized. Исправление подготовлено; обычный SDK без pacing проходит
подключение, список инструментов, создание и чтение синтетического кандидата.
Схема БД, параметры авторизации, почта и Telegram не меняются.

Независимый retest: 9 PASS, 0 FAIL, 0 SKIP. Проверены переполнение, дедлайн,
отмена, shutdown, отказ зависимости, отзыв MCP/owner во время ожидания,
стандартный SDK и каждый интервал допуска двух экземпляров приложения.
Найденная потеря аудита Q-01 исправлена: 70 итоговых 429 дают 70 завершившихся
записей при задержанной, но успешной зависимости. Отдельный предел audit backlog
не заявляется; при медленной БД он может расти. Подробности и runtime fingerprint
в новом QA. Исторический отчёт не используется как доказательство новой очереди.
