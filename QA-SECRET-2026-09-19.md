## Ограниченная AppSec-проверка

Затронутые активы: право публикации в единственный канал, bot token, секрет маршрута, порядок/кратность частей. Граница доверия: внешний клиент → Timeweb TLS/proxy → capability URL → MCP → фиксированный Telegram adapter. Проверены только затронутые auth/config/transport/admission потоки, а не всё приложение или платформа.

Обязательных нарушений в проверенном локальном scope не обнаружено. Статический обзор подтвердил: случайный секрет генерируется `crypto.randomBytes(32)`; строгий raw path сравнивается через `timingSafeEqual`; секрет не включается в startup logs; channel фиксирован; новые данные/секреты не пишутся на диск приложением. Тестовые fixtures намеренно содержат синтетические известные значения и не предназначены для развёртывания.

Принятые владельцем риски MVP сохраняются: держатель полного URL имеет все доступные права, URL может попасть в журналы/настройки/скриншоты, персональных прав и отзыва отдельного клиента нет. Замена capability требует обновить переменную и переподключить клиент. RAM rate limit/registry сбрасываются при перезапуске; лимит относится к новым сказкам, не является общей защитой от DoS и не ограничивает число частей одной разрешённой сказки.

**TLS остаётся внешним обязательным условием.** HTTPS origin в конфигурации и X-Forwarded-Proto не доказывают шифрование. При отсутствии X-Forwarded-Proto приложение доверяет платформе. Для боевого URL необходимы действительный сертификат и настройка HTTP redirect/reject на доверенном proxy; клиент не должен отправлять секрет или текст по HTTP. Реальный домен `rtalyutin-tg-mcp-fb9b.twc1.net` этим агентом не вызывался и его TLS не проверялся. Reverse-proxy access logs, прямой доступ к контейнеру, настоящие секреты, IdP/OAuth, ChatGPT UI/background и реальные Telegram права/публикации вне этой приёмки.
