# Передача публикации инструменту

Версия 0.6.0, 19.09.2026. Блок подготовлен, но не применён к действующей
задаче: внешний MCP и вызов из фонового запуска ещё не подтверждены.
Генерация остаётся в существующей задаче ChatGPT; инструмент отвечает за
разбиение и отправку готового текста. Он не читает соседние чаты сам.

## Условия включения

G2: согласованный и проверенный способ аутентификации. G1: успешный
аутентифицированный вызов именно из фонового запуска, не ручного чата.
G3: отдельно разрешённая проверка реальной доставки и прав канала.
Перед включением перечитать текущие инструкции и расписание генератора;
добавить только блок ниже, сохранить остальные инструкции и расписание.
При наличии обновлений владельца не восстанавливать старую копию prompt.

## Блок для добавления к текущей инструкции после закрытия условий

После подготовки окончательного текста сказки передай публикацию подключённому
инструменту. Сохраняй действующие требования к самой сказке и выводу в ChatGPT.
Иллюстрацию продолжай создавать по текущей инструкции; её отправка в Telegram
пока не согласована (Q2), поэтому в вызов публикации включай только текст.

1. Вызови get_publisher_status с пустым объектом. Продолжай только если
   publish_enabled=true, telegram_ready=true, reason_code=null и получен
   instance_id. При недоступности инструмента сохрани сказку в ответе ChatGPT
   и сообщи, что публикация не выполнена. Не отправляй через другой сервис.
2. Для одного выпуска используй стабильный story_id вида
   «bear-story:YYYY-MM-DD», где дата — дата выпуска по Europe/Moscow, а не
   момент повторного запуска. Один выпуск в день. Создай один UUID attempt_id
   и сохрани его вместе с instance_id в контексте текущего выполнения до вызова.
3. Вызови publish_story ровно один раз: story_id, attempt_id,
   expected_instance_id из шага 1, text — полный окончательный текст сказки
   с заголовком и исходными абзацами. Markdown-ограду блока кода из ответа
   ChatGPT в текст НЕ включай: это оболочка вывода, а не часть сказки.
   Не разбивай, не пересказывай, не сокращай и не нумеруй части самостоятельно.
   Не передавай chat_id/токены/параметры форматирования: канал задан сервером.
4. Только PUBLISHED подтверждает завершённую публикацию. Сохрани возвращённые
   message_id по порядку. Не придумывай ссылки: message_url пока null.
5. При потерянном/непонятном ответе, таймауте или IN_PROGRESS разрешён только
   get_publish_attempt с теми же attempt_id и expected_instance_id. Повторное
   publish_story, создание нового attempt_id или нового story_id для обхода
   результата запрещены. Если чтение не подтверждает PUBLISHED, остановись и
   сообщи владельцу известные ID и необходимость проверки канала; бесконечно
   не опрашивай. PARTIAL/UNKNOWN требуют ручной проверки, оставшиеся части
   автоматически не отправляй. REJECTED/BUSY также не повторяй автоматически.
6. При смене instance_id, потере контекста предыдущей попытки или подозрении
   на повтор того же выпуска сначала нужна ручная проверка Telegram. Память
   сервера временная: одинаковый story_id не защищает от дублей после рестарта.

Ручную досылку нельзя начинать при IN_PROGRESS. Она возможна только после
терминального результата или подтверждённой остановки обработчика и сверки
канала; обрыв MCP сам по себе не доказывает остановку. Даже остановка процесса
не отзывает уже начатый запрос к Telegram.

Не включай служебные результаты, ошибки или IDs в текст сказки, отправляемый
в канал. Если публикация не подтверждена, короткий служебный статус в ChatGPT
допустим как исключение к прежнему требованию вывода только сказки/обложки.
Никогда не сообщай «опубликовано» по факту создания текста или вызова инструмента.

## Как проверить перенос ответственности

На mock/integration: одна полная сказка → один publish_story → последовательные
sendMessage; совпадение конкатенации текста, проверка IDs. На UNKNOWN второй
части — никаких повторов/третьей части, только чтение попытки. Недоступный MCP
и stale instance → отсутствие отправок. Работающий ручной вызов не доказывает
доступ из фоновой задачи. Включение блока без G1 не считается завершением проекта.
