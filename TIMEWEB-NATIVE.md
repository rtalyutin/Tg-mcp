# Timeweb: MVP без Auth0 и собственного Dockerfile

Пакет 0.9.0. Владелец 19.09.2026 согласовал секретную ссылку после объяснения
рисков и предоставил технический домен `rtalyutin-tg-mcp-fb9b.twc1.net`.
Развёртывание 0.8.0 владельцем завершилось ошибкой после успешной сборки.
Локально воспроизведено: без OAuth-настроек старый процесс завершался до listen.
Путь `dist/production-main.js` и привязка `0.0.0.0` корректны.

## Поля формы

| Поле | Значение |
|---|---|
| Репозиторий / ветка | rtalyutin/Tg-mcp / main, новый проверенный commit 0.9.0 |
| Фреймворк / версия | Express / Node.js 24 |
| Команда сборки | `npm ci --include=dev --ignore-scripts && npm run build` |
| Зависимости | пусто |
| Команда запуска | `npm run start:production` |
| Путь проекта | пусто (корень) |
| Проверка состояния | `/healthz` |
| Приватная сеть | не нужна |
| Процессы / реплики | один; без cluster и перекрывающегося rolling reload |
| БД / постоянный том | не нужны |

Платформа сама собирает контейнер. Собственный Dockerfile не используется.
[Официальная инструкция Express](https://timeweb.cloud/docs/apps/deploying-backend-applications/express).

## Переменные первого запуска

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=8080
MCP_AUTH_MODE=secret_path
MCP_PUBLIC_ORIGIN=https://rtalyutin-tg-mcp-fb9b.twc1.net
MCP_PROFILE=readonly
PUBLISH_ENABLED=false
```

Ещё одна обязательная переменная: `MCP_PATH_SECRET` — 64 hex-символа из
32 криптографически случайных байт. После скачивания репозитория на своём
компьютере с Node выполнить `npm run --silent secret:generate`. Это команда
для приватной генерации, НЕ команда сборки/запуска Timeweb: её stdout — секрет.
Вставить результат только в переменную Timeweb. Не использовать пример/пароль,
не помещать секрет в репозиторий, команды сборки, описание приложения или чат.

`OAUTH_ISSUER`, `OAUTH_JWKS_URI`, `OAUTH_ALLOWED_SUBJECT`, `MCP_RESOURCE_URL`
в этом режиме не нужны; старые значения можно удалить. Никакой регистрации
в Auth0. Токен Telegram для readonly тоже не требуется.
`npm run check:config` выводит CONFIG_VALID без сети/порта или точное имя
недостающего поля без его значения. Приложение не загружает .env-файл само:
переменные задаются в Timeweb. На неверной конфигурации запуск закрыт.

## После пересборки

1. Открыть `https://rtalyutin-tg-mcp-fb9b.twc1.net/healthz`: ожидается
   HTTP 200, JSON `{"status":"ok"}`. Проверка Timeweb допускается с внутренним
   Host и без секрета. Это доказывает доступность процесса, не Telegram.
2. Подключить в ChatGPT MCP с вариантом без OAuth (`noauth`), полный адрес:
   `https://rtalyutin-tg-mcp-fb9b.twc1.net/mcp/<значение MCP_PATH_SECRET>`.
   Угловые скобки заменить самим значением. Не открывать секретный адрес
   обычной вкладкой; GET на нём возвращает 405, это ожидаемо.
3. Вызвать `get_publisher_status`. В readonly доступен только этот инструмент,
   `publish_enabled=false`, `telegram_ready=false`. Внешние Telegram-запросы
   в этом профиле отсутствуют. Успешный ручной вызов не закрывает фоновый gate.
4. Проверить отдельно фоновый вызов согласно `INTEGRATION-GATE.md`.
   Задачу генерации и расписание этим выпуском не менять.

Использовать только HTTPS. Настроенный HTTPS origin не включает TLS на
платформе сам: сертификат и маршрутизацию проверить в Timeweb. Проверка
публичного `/healthz` из среды разработки 19.09.2026 получила 502 при
успешной проверке TLS; рабочий endpoint пока не подтверждён. Не передавать
секрет по HTTP даже в расчёте на автоматический редирект.
Прокси должен сохранять исходный Host. Явный `X-Forwarded-Proto: http`
отклоняется; отсутствие заголовка не является доказательством шифрования.

## Публикация — отдельное включение

После проверки доступа и разрешения на Telegram-публикацию выставить
`MCP_PROFILE=publisher`, `TELEGRAM_BOT_TOKEN`, фиксированный числовой
`TELEGRAM_CHANNEL_ID` вида `-100…`. Боту нужны права администратора канала
и публикации сообщений. Включать `PUBLISH_ENABLED=true` только для
согласованной проверки/запуска. До этого публиковать нельзя.

Один Publisher на процесс, отправка частей по порядку. Не чаще одной новой
сказки в 60 секунд; известные попытки и чтение не блокируются этим лимитом.
Нет очереди и автоматических повторов. Timeout/обрыв после отправки — UNKNOWN
и ручная проверка канала. Перезапуск теряет RAM; не воспроизводить прошлый
выпуск автоматически. SIGTERM/SIGINT останавливают новые части, ожидая исход
текущего запроса. Реальный grace period платформы пока не проверен.

## Риск и отзыв секретной ссылки

Полная ссылка равносильна ключу ко всему профилю. Возможны утечки через логи
прокси/настройки подключения/скриншоты; приложение не логирует её, но не
контролирует журналы Timeweb или ChatGPT. Лимит в RAM не является общей
защитой от атак и сбрасывается при рестарте. Личных аккаунтов, scopes,
автоматического истечения ключа и персонального отзыва в этом MVP нет.

При утечке: `PUBLISH_ENABLED=false`, остановить старый процесс, сгенерировать
новый секрет, заменить переменную, запустить один процесс и переподключить
ChatGPT новым URL. Текущая отправка может успеть завершиться; проверить канал.
Старый URL возвращает 404 после остановки старого экземпляра. Ротация ключа
не восстанавливает историю попыток. HTTP без секрета не даёт MCP-доступа.

OAuth остался отдельной альтернативой в `OAUTH-SETUP.md`; не переключать
обратно на него ради обязательного внешнего IdP для этого MVP.
