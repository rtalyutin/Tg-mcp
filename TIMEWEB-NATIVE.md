# Timeweb: запуск MVP без ключей MCP

Версия 0.10.0, 19.09.2026. Выбор владельца: без Auth0 и секретной ссылки.
На присланном экране поля сборки/запуска/healthcheck подходят. После обновления
main достаточно сохранить настройки и запустить новую пересборку.

| Поле | Значение |
|---|---|
| Ветка | main, проверенный новый commit 0.10.0 |
| Фреймворк / версия | Express / Node.js 24 |
| Сборка | `npm ci --include=dev --ignore-scripts && npm run build` |
| Зависимости / путь проекта | пусто |
| Запуск | `npm run start:production` |
| Проверка состояния | `/healthz` |
| Переменные первого запуска | не нужны |
| Процессы / реплики | один, без cluster и rolling overlap |

Дефолты: публичный read-only `/mcp`, HOST 0.0.0.0, PORT 8080,
MCP_PUBLIC_ORIGIN=https://rtalyutin-tg-mcp-fb9b.twc1.net,
PUBLISH_ENABLED=false. PORT и MCP_PUBLIC_ORIGIN можно переопределить
несекретными переменными, если площадка изменит порт/домен.
Никаких внешних запросов Telegram или OAuth в этом профиле нет.
Пустая конфигурация теперь допустима; отсутствие обязательных OAuth-полей
больше не вызывает падения при первом запуске без авторизации.

Если старые auth-переменные всё-таки были добавлены, удалите их или явно
задайте `MCP_AUTH_MODE=public`. Неполная старая auth-конфигурация специально
не превращается в публичный доступ автоматически. Старый Timeweb-MVP.env
с ключом маршрута больше не нужен; актуальный optional .env.production.example
не содержит ключей. Автозагрузка .env приложением не реализована.

## Проверка и подключение

1. `https://rtalyutin-tg-mcp-fb9b.twc1.net/healthz` должен вернуть 200 и
   `{"status":"ok"}`. Health принимает внутренний Host платформы и не
   раскрывает информацию канала.
2. В ChatGPT указать `https://rtalyutin-tg-mcp-fb9b.twc1.net/mcp`, без OAuth.
   У URL нет дополнительного сегмента или параметра с секретом.
3. Вызвать get_publisher_status: version 0.10.0, publish_enabled=false,
   telegram_ready=false. Доступен один read-only инструмент.
4. Отдельно проверить реальный фоновый вызов; ручной не закрывает G1.

GET на /mcp возвращает 405 — это нормально для POST MCP endpoint. Не считать
открытие его обычной вкладкой тестом подключения. Использовать HTTPS; реальная
TLS termination, сохранение Host и proxy timeout проверяются на Timeweb.
На предыдущей версии публичный health из среды разработки давал 502; новый
деплой и работоспособность приложения снаружи агентом не подтверждены.

## Что означает отсутствие авторизации

Закрытие репозитория GitHub ограничивает просмотр исходников, но не обращения
к приложению. Сейчас анонимно читается только технический статус. Public-mode
publisher, если его включить позже, доступен любому по домену. Это явное свойство
выбранного режима, не защита приватностью репы. Host/Origin, строгий JSON/лимиты
и rate limit не являются аутентификацией и не защищают от постороннего HTTP-клиента.

Для отправки Telegram всё равно требует bot token. При отдельно разрешённой
активации добавить MCP_AUTH_MODE=public, MCP_PROFILE=publisher,
TELEGRAM_BOT_TOKEN, фиксированный TELEGRAM_CHANNEL_ID и PUBLISH_ENABLED=true.
Для нескольких заданий вместо TELEGRAM_CHANNEL_ID используется
TELEGRAM_TASK_CHANNELS: список пар `task_id=числовой_ID_канала` или
`task_id=@публичное_имя_канала`, разделённых
запятыми. Задание передаёт `task_id` в вызове `publish_story`. Сначала
проверять права бота с PUBLISH_ENABLED=false. Поле команды запуска Timeweb
может передать эти настройки через `env`; токен тогда виден в настройке и
возможно в журналах платформы. Договорённость на этот компромисс относится
к MVP. Пример команды есть в README.
Не помещать bot token в публичный или приватный Git, команду запуска или логи.
Публикация без явного выбора public-профиля не включается. Параметры доступны
в прежних oauth/secret_path альтернативах, но они не требуются для текущего выбора.

Одна новая сказка в 60 секунд, один процесс; несколько частей одной сказки идут
по порядку. Никакой очереди/автоматической досылки/повтора после UNKNOWN.
Дедупликация и лимит только RAM, перезапуск их стирает. При неизвестном результате
остановиться и вручную проверить канал. SIGTERM/SIGINT прекращают новые части и
ждут исход текущего запроса; реальный grace period платформы не проверен.

Источник нативного размещения:
[Timeweb Express](https://timeweb.cloud/docs/apps/deploying-backend-applications/express).
Поддержка noauth в клиенте:
[OpenAI Authentication](https://developers.openai.com/plugins/build/auth).
Оба источника подтверждают механизм, а не реальную интеграцию конкретного аккаунта.
