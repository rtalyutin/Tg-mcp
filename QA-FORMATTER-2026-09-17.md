# Независимая проверка форматтера — 17.09.2026

**Вердикт: PASS в локальной области проверки.** Реальные Telegram, Timeweb,
OAuth и фоновый вызов MCP этой проверкой не подтверждаются.

Проверена версия пакета `0.3.0`, Node.js `v24.19.0`.
Проверяющий не изменял реализацию и авторские тесты; добавлен отдельный
`test/formatter-independent.test.ts` с 8 группами тестов.

## Фактические проверки

1. **Выполнимость разбиения:** 32 760 комбинаций строк из `a`, пробела,
   перевода строки и эмодзи, глубина 1–6, лимиты 1–6 UTF-16 units.
   Независимый oracle перебирает все допустимые разбиения по границам графем;
   не использует суффиксный DP или ранжирование реализации. Сопоставлены
   существование решения и принятие/отклонение форматтером; ложных отказов
   или принятия невыполнимой строки не обнаружено.
2. **Смешанный Unicode:** 1000 воспроизводимых случаев с CRLF, combining mark,
   ZWJ-семейством, флагом, эмодзи, пунктуацией и U+2029; тот же независимый
   перебор и повторная проверка детерминированности.
3. **Приоритеты:** конкретные ожидания первого разреза по абзацу, предложению
   и слову; пробелы и CRLF остаются в тексте. Для всех принятых случаев
   конкатенация точна, части непусты после `trim`, в пределах лимита и заканчиваются
   на границе графемы полного исходного текста.
4. **Предварительный отказ:** неделимая графема размером 4097 UTF-16 units после
   валидного вступления даёт `TEXT_GRAPHEME_TOO_LONG` и ноль вызовов mock sender.
   Проверены пустые/пробельные строки, lone surrogates, неверные лимиты,
   математически неразбиваемый пробельный промежуток.
5. **Реальный верхний предел входа:** ASCII-текст ровно 256 KiB опубликован
   тестовым адаптером как 64 части, точная конкатенация; дополнительный байт
   отклонён, счётчик отправок не вырос. Эмодзи-текст ровно 256 KiB также разбит
   без потерь и разрыва графем.
6. **UNKNOWN с реальным форматтером:** первая часть подтверждена, вторая
   неопределённа, третья и следующие не отправлены. Индексы, подтверждения и
   остаток верны; `manual_check_required=true`, `automatic_retry_allowed=false`.
   Повтор исходного запроса, запрос той же сказки с новым attempt ID и чтение
   статуса не запускают дополнительных отправок.
7. **PARTIAL/исключение:** явный отказ второй части (`RATE_LIMITED`) даёт
   `PARTIAL`; исключение тестового адаптера на второй части даёт `UNKNOWN`.
   В обоих случаях обязательна ручная проверка, автоматического повтора нет.
8. **Защита внутреннего форматтера:** намеренно испорченные границы combining
   sequence, пары regional indicators, ZWJ и CRLF отклонены целиком до отправки.

## Воспроизведение

Из корня проекта после `npm ci`:

```sh
node --test test/formatter-independent.test.ts
npm test
npm run check
sha256sum src/formatter.ts src/publisher.ts
```

Фактические результаты: независимые **8/8 PASS**, полная регрессия
**39/39 PASS**, `tsc --noEmit` **PASS**. Нет пропусков, отмен или падений.
В журнале npm есть предупреждение об окруженческом `http-proxy`; оно не
изменило успешные exit codes проверок.

## Граница доказательства

- Oracle независим по алгоритму поиска разбиений; границы Unicode оба пути
  получают из стандартного `Intl.Segmenter` текущего Node/ICU. Это не независимая
  реализация Unicode UAX #29 и не проверка отображения каждым Telegram-клиентом.
- 4096 UTF-16 units — консервативный внутренний бюджет, не экспериментальное
  доказательство фактического подсчёта символов Telegram.
- Проверены mock-отправки и локальный read-only MCP probe. Не использовались
  токен бота, реальный канал, облачный деплой или внешние публикации.
- Тест верхнего предела проверяет допустимый размер входа, не SLA и не
  исчерпывающую нагрузочную устойчивость для всех возможных Unicode-строк.
- Перезапуск по-прежнему уничтожает RAM-реестр; глобальная дедупликация
  и восстановление истории без хранилища не обещаются.

Открытых дефектов по проверенной области не обнаружено. Следующий этап —
Telegram-адаптер и его сетевые mock-проверки; этот отчёт не разрешает реальную
публикацию или развёртывание.
