# Первая проверяемая выборка Dashboard

Снимок хранится отдельно от публичного репозитория. Его текущая версия содержит
пять проектов, 13 задач и три включённые автоматизации, считанные 24.09.2026.
Источник каждой задачи указан в `sources`; отсутствие записи означает неполный
охват, а не отсутствие деятельности. Исключённый владельцем проект не входит
в снимок. Импортёр отклоняет включение проекта из частного списка исключений
и задачу со связью на
неизвестный или исключённый проект. При будущем импорте из бесед это исключение
надо применить **до извлечения содержимого** соответствующей папки/проекта;
название в текущем снимке само по себе не фильтрует будущий сборщик.

## Установка в личную PostgreSQL

1. Под административной ролью выполнить `npm run migrate` внутри `dashboard/`;
   миграция 004 создаёт единственную таблицу `dashboard.curated_snapshot`.
2. Создать отдельную роль входа `dashboard_snapshot_reader` с закрытым паролем
   и правом CONNECT на личную базу. Под миграционной ролью выполнить
   `dashboard/sql/grant-snapshot-reader.sql`. Проверить, что роль читает только
   эту таблицу и не имеет прав записи или чтения исходных сообщений.
3. Из локально сохранённого приватного JSON выполнить
   `DASHBOARD_MIGRATION_DATABASE_URL=... npm run import:snapshot -- /path/to/private-snapshot.json`
   внутри `dashboard/`. Команда выдаёт digest и количество записей, не выводя
   их содержимое. Повтор того же файла безопасно обновляет одну строку.
4. Указать в приложении `DASHBOARD_SNAPSHOT_READ_DATABASE_URL` для отдельной
   роли чтения. Другая рабочая роль `DASHBOARD_DATABASE_URL` и её права не
   подменяются. Перезапустить приложение и открыть `/dashboard/` после входа
   владельца через существующий `/login`.

`GET /dashboard/api/snapshot` проверяет действующую cookie владельца до запроса
в личную БД. Публичный `/dashboard/` продолжает показывать только старый демо
экран. Ответ 401 означает отсутствие сессии; 404 — закрытый маршрут не включён;
503 — строка не загружена или БД временно недоступна. Все ответы `no-store`.
В реальном экране четыре примерных этапа заменяются нейтральным «Этап не
определён»: словарь состояний владелец пока не утвердил. Входящие, приоритеты
и журнал изменений оставлены пустыми, поскольку их актуальность не проверена.

## Граница проверки

Локальные HTTP тесты проверяют отказ без сессии и доступ с синтетической
сессией; PGlite проверяет миграцию, readback и запрет исключённого проекта.
Это не проверка роли и TLS на Timeweb. До реального включения нужны
миграция, создание роли, безопасная передача файла, чтение после входа и
независимая проверка отсутствия данных в публичных ответах.
